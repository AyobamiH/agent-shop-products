# Problem-Centred Institutional Memory

Build a problem-centred record that another agent can resume without promoting remembered success into fact.

## Set the retrieval boundary

Record the requested time window, known workstreams, available account search, exports, saved indexes and current repository access. Use supported search or file connectors. If search fails, record the failure and continue with available checkpoints; never describe metadata enumeration as reading complete chats.

Read the existing index schema and checkpoint before creating a competing index. Preserve stable IDs, foreign keys and original source locators. Keep private transcript text, account identifiers and credential material outside public outputs.

## Separate problems, attempts and evidence

Give each enduring problem one stable identity. Add a dated attempt for each materially different intervention, including failed, abandoned and partial attempts. Link attempts to the problem and their sources instead of creating a new problem for every recap.

For each source, record its date, kind, context, access depth and limitation. Distinguish an original user observation, a runtime receipt, repository state, an assistant claim and a later summary. A source referenced by an index has not necessarily been retrieved.

Preserve contradictions and the timeline. Mark a later result as superseding the earlier blocker only within the scope it actually tested. Do not erase useful failure history or generalise one account's result to all customers.

## Qualify outcomes

Keep completion, verification and applicability separate. Use the canonical schema's states, with these minimum distinctions:

- Verified: appropriate observable evidence supports the specific outcome.
- Partial: an explicit part passed while other acceptance layers remain open.
- Unresolved: evidence is absent, contradictory or only an assistant assertion.
- Superseded: a later identified attempt replaces an older result within a stated scope.

Retain inherited labels when needed for traceability, but add the current evidence-qualified state. Do not count an inherited “verified” label as verified when its only support is a prior assistant statement.

## Extract reusable procedures

Group equivalent interventions by problem and mechanism. Count distinct evidenced occurrences, not copies of the same summary. Separate supported recurring patterns from candidate opportunities.

Promote a procedure only when the records explain its trigger, actions, observable acceptance and limits. Map it to an existing owned skill before creating another product. Keep design briefs and speculative projects as candidates when implementation evidence is missing.

Historical requests describe what happened; they do not authorise new deployments, account deletion, campaign publication or messages now. Take consequential actions only within the current task's authority.

## Validate and checkpoint

Check unique IDs, referenced IDs, source links, attempt ordering and summary counts. If a spreadsheet is the canonical index, compare the written cells with the intended records and keep its native structure. Record what was actually checked.

Save a resumable checkpoint with completed retrieval, unresolved contradictions, a prioritised retrieval queue and the next acceptance step for each active workstream. Report corpus size, records inspected and directly retrieved material separately. Do not calculate account-wide coverage without a known complete denominator.

Return a concise continuation brief and a source-backed index. For public reuse, publish original generalised procedures and sanitised provenance rather than private transcripts.

Read [calibration cases](references/calibration-cases.md) when deciding whether to qualify or merge a historical claim.
